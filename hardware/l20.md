# NVIDIA L20

Facts that change optimization decisions. Checked 2026-10-12 on the user's shared build runner with the commands below; confirm on the production machine.

## Key numbers
- Architecture: Ada Lovelace (AD102), compute capability 8.9 (sm_89).
- 92 SMs; 48 GB GDDR6 on a 384-bit bus, about 864 GB/s. ECC was on, which leaves 46068 MiB.
- L2 cache: 96 MB.
- Host link: PCIe 4.0 x16. No NVLink.
- Power limit 350 W as reported; the application clock was fixed at 2520 MHz, so clocks hold unless power or heat caps them.
- The runner's host: 16 CPU threads, 123 GB RAM, no swap, no conda, host CUDA 12.1 only; a driver of the 580 series runs CUDA 13 images.

## What follows from them
- Half the memory bandwidth of an RTX 5090 and a slower host link: memory-bound and transfer-bound stages lose more than compute-bound ones. Measure; data-sheet ratios do not predict a workload.
- Frameworks may ship no sm_89 kernels and run sm_86 binaries on it (same major); check `torch.cuda.get_arch_list()`. A TensorRT plan built on another GPU model does not load: build one per model, named by compute capability.
- Floating-point results differ from another GPU model's, so references frozen there are graded, not reproduced; `rules/benchmarking.md`.
- Tensor cores take FP8 but not FP4; a precision change still needs the user's approval.
- 46 GB bound batch size and model size, more than on the 5090; cold start and engine builds take longer.
- A shared runner also hosts CI and test deployments: coordinate runs there, expect noise from other jobs, and give every heavy job its own memory cap (`systemd-run` on the host, `docker run --memory` in a container, at most half its RAM); no memory guard watches it.
